# jev × LLM 判定対決ビューア

同じ user の発言を TypeSafe の `jev` と LLM の両方に判定させ、判定結果のズレと速度差を1画面で見せるデモ。判定は [affectus](https://github.com/n-yokomachi/affectus) の感情状態として別々に蓄積され、2つの状態が会話の進行につれて分岐していく様子をプルチックの輪で見られる。さらに、分岐したそれぞれの感情状態で同じ発言への返答を生成するので、判定の差が2つの返答の違いとして読める。

両者が受け取るのは、判定の直前に読んだ自分の現在の8軸と user の発言。affectus の agent は毎ターン自分の状態を読んでから感情の動きを申告するので、判定の入力にも現在値が要る。各側は自分の状態を読むため、状態が分かれた2ターン目以降は入力も分かれる。比較の公平性は、同じ状態から出発する最初の判定で見る。

## 必要なもの

- macOS（Apple Silicon / Intel のどちらでも）
- Node 24 以上
- Vercel AI Gateway の API キー

配布 zip には affectus のバイナリと `node_modules` が入っているので、Go もネットワーク越しの依存解決も要らない。

## 使い方

```bash
bash scripts/setup.sh
# 案内に従って .env.local に API キーを書く
node --env-file=.env.local src/server.ts
```

ブラウザで http://localhost:8787 を開く。

シナリオを選ぶと、会話が1ターンずつ流れる。`▶❙` で1ターン進め、`▶` で自動再生。中央の入力欄から任意の発言を判定させることもできる。

上部の**人格**は、返答を生成する話し手の性格。`friendly`（明るく協力的）と `contrarian`（天邪鬼）の2つがあり、**両側とも同じ人格を使う。** シナリオを選ぶと、そのトランスクリプトが記録された当時の人格が自動で選ばれる（ファイル名に入っている）。送信前なら手で変えられる。判定には人格を与えない。

## 画面の読み方

- **中央**に出るのは user の発言、判定のずれ、手入力欄だけ。記録された返答も当時の自己申告も使わないし、出さない
- **左が LLM、右が jev。** 同じ発言を同時に判定させ、先に返ったほうから埋まる
- **プルチックの輪**は花弁の長さが各軸の強さ。左右で形が違えば、判定が食い違っている
- **軸ゲージ**は中央線から右が正、左が負。jev 側の点線は、jev が軸ごとに返す確率分布からこちら側で算出した確信度。LLM 側はその分布を返さないため点線が出ない
- **判定のずれ（8軸の差の合計）** は両者のデルタがどれだけ離れているかの1数値。0 なら完全一致で、上限は 16
- **判定 / 生成の ms** は別の数字。上が判定、下がそのあとに走る返答生成。生成は両側とも同じ Haiku 4.5 なので、速度差として読むのは判定のほう
- **生成された返答**は両側で同じモデル・同じ人格・同じ指示文を使い、違うのは渡す感情状態だけ。読み比べると、判定の差がそのまま口調の差になっている。人格を固定して判定器だけを変えているので、見えているのは「同じ人格でも、判定器が違えば別人のように振る舞う」という差
- **判定の入出力（JSON）** はパネルの一番下に常に出ている。そのターンでモデルに渡した内容と返ってきた内容がそのまま読める。枠は高さ固定で、長い JSON は枠の中でスクロールする。対象は判定だけで、返答生成の入出力は出さない

## 構成

| ディレクトリ | 内容 |
|---|---|
| `src/` | サーバーと判定ロジック |
| `public/` | 画面 |
| `data/transcripts/` | 再生用の会話ログ 24 シナリオ × 20 ターン |
| `bin/` | affectus バイナリ |
| `state/` | 2つの感情状態（`setup.sh` が生成） |

```bash
npm test
```

## 配布 zip を作る

```bash
./scripts/package.sh
```

`dist/` に zip ができる。API キーと感情状態は含まれない。
