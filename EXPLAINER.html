LLM と jev のレスポンスと精度を分析するためのデモです。 同じ発言を両者に判定させ、判定のずれと応答速度を並べて見比べます。

affectus とは

感情の状態だけを持つ道具

affectus は LLM エージェント用の感情状態エンジンです。プルチックの8感情を それぞれ 0.0〜1.0 の値として保持し、時間が経つと baseline に向かって減衰します。

特徴は、数値の解釈を一切しないことです。affectus が返すのは8つの数字だけで、 「いまは喜びより悲しみが強い」と読むのも、それを口調に反映させるのも LLM の仕事。 状態を持つ側と、意味を与える側を分けてあります。

処理フロー

1ターンで起きること

01

LLM / jev が現在の感情と発言を受け取る

いまの8軸の値と、user が言った一文。両方に同じ形で渡します。 既に怒りが高ければ、さらに煽られても伸びしろは小さい — その依存を含めて判定させます。

02

それぞれが感情の変動値を返す

8軸それぞれ −1.0〜1.0 で、この発言を受けて感情がどう動くかを答えます。

LLM

構造化出力で8軸の数値を一度に返す。文章を書ける普通のモデル。

jev

8問を1リクエストで並列に。文章は一切生成しない。

03

それぞれレスポンスからの感情パラメータを更新

返ってきた変動値を、別々の affectus に適用します。状態ファイルが2つあり、ターンを重ねるごとに離れていきます。

04

変更された感情パラメータをもとに LLM が回答生成する

各側の8軸を読ませて返答を書かせます。両側とも同じモデル・同じ人格・同じ指示文で、 違うのは渡す感情パラメータだけ。返答の差は判定の差にだけ由来します。

jev の答え方

1つ選ぶのではなく、確率を振る

jev は5段階のどれか1つを選ぶのではなく、5段階すべてに確率を振って返します。 「そういう言い方されると、正直ちょっと疲れるんだけど。」に対する受容の答えが、実際にはこうでした。

強く下がった  0.01
下がった      0.53  ███████████
変化なし      0.16  ███
上がった      0.29  ██████
強く上がった  0.01

この分布を確率で重み付けした平均が、返ってくる score = 1.74 です。 「変化なし」にあたる 2.0 をわずかに下回る位置。そこから決まった式で −1.0〜1.0 に写して、 変動値 −0.13 になります。

段階を1つ選ばせるのではなく分布で返るので、迷いの度合いがそのまま値に出ます。 この例では「下がった」0.53 と「上がった」0.29 に割れていて、その綱引きの結果が 「ほぼ動かない」という小さな値に落ち着いています。1つ選ばせていれば −0.5 になっていたところです。

人格

感情は、増幅する対象を必要とする

affectus の検証では、これは「人格 system prompt が指示する方向への応答感度を上げるアンプ」 として作用すると結論されています。アンプには増幅する対象が要ります。 人格が空のままでは、感情は色をつける先を持ちません。

そこで話し手に性格を与えます。2種類あり、画面から切り替えられます。

friendly

明るく協力的。相手の話を肯定的に受け止め、情報よりも気持ちに寄り添う。

contrarian

天邪鬼。素直に同意せず、皮肉や反論を交える。ぶっきらぼうで距離がある。

両側とも同じ人格を使います。変えるのは判定器だけ。 人格という定数を固定したうえで判定器だけを動かすので、見えているのは 「同じ人格でも、判定器が違えば別人のように振る舞う」という差になります。

判定側には人格を与えません。判定は「この発言で感情がどう動くか」であって、人格の演技ではないからです。

画面

どの軸で割れたかを見る

中央に8軸ぶんの対比が並びます。中央が 0、左右の末端が 1.0。 左が LLM、右が jev で、棒の長さがその軸をどれだけ動かしたかです。

符号は色が持ちます。正はその側の色、負はくすんだ灰。 長さが同じで色が違えば、両者は正反対の判断をしています。 長さだけで見ると「片方が大きく動いた」としか読めない場面です。

中央の数値はその軸の差で、符号付きの値どうしの差。 LLM が −0.5、jev が +0.5 なら 1.00 になります。

左右のパネルには、感情の輪（affectus の蓄積状態）、判定と生成それぞれの所要時間、 生成された返答、そしてモデルに渡した内容と返ってきた内容の JSON がそのまま出ます。

なぜ jev を試すのか

感情の更新は、会話の外側の処理

これまでの課題は時間でした。文章を読ませて現在の状態から感情パラメータの 変動値を出させる、という処理を LLM にやらせると、どうしても時間がかかります。

しかもこれは、ユーザーに見せる応答そのものではありません。応答を書く前段の内部処理です。 そこに数秒かかるのは重く、組み込む場所を選びます。

jev は同じ判定を一瞬で返します。レイテンシを気にしなくてよくなるため、 会話のたびに走らせても構わない処理になります。それが、この比較を作った理由です。
